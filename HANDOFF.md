Документ для передачи работы в новую сессию. Здесь — что уже сделано, **почему

## 1. Что это за проект

Личный инструмент проверки автомобиля перед покупкой по израильским открытым
госданным (data.gov.il). Две части:

1. **Живой поиск** по номеру машины — марка, год, пробег на последнем тесте,
   VIN, владение, отзывы, комплектация. Данные тянутся напрямую из data.gov.il
   в момент запроса. Работало с самого начала.
2. **Накопленная история** — то, чего нет ни у кого: как менялся пробег по датам
   техосмотров, смена номера двигателя, аномалии (скрутка одометра), подробный
   журнал изменений. Государство публикует только *текущий* срез, историю
   мы копим сами, снимок за снимком.

Репозиторий: **https://github.com/komikagze/carcheck** (публичный).

локальная копия базы как независимый бэкап.

## 4. Решения и почему именно так (НЕ переигрывать без причины)

### 4.1 Интерфейс на иврите, комментарии на русском
Пользователь — ивритоязычная аудитория, и данные из data.gov.il **уже приходят
на иврите**. Поэтому весь UI переведён на иврит, `<html lang="he" dir="rtl">`,
CSS выправлен под RTL. Словарь `VALUE_TRANSLATIONS` (иврит→русский) **удалён
намеренно** — переводить значения теперь незачем, это был источник ошибок.
`translate_val` / `translateVal` оставлены как passthrough, чтобы не трогать
все места вызова.

Комментарии в коде, README, FILES.md — **остаются на русском**, это заметки
разработчику для себя. Проверено: кириллицы в самом интерфейсе нет.

### 4.2 JSON API вместо скачивания CSV
CDN `e.data.gov.il`, откуда раньше качались сырые CSV, стоит за защитой от ботов
(JS-челлендж, `Via: 1.1 google`). Обычный HTTP-клиент получает HTML-заглушку
вместо файла — проверено вживую, в браузере тот же URL отдаёт нормальный CSV.

Решение: `collector/api_loader.py` тянет данные постранично через
`datastore_search` — **тот же самый официальный публичный API**, которым уже
пользуется живой поиск. Это не обход защиты, а другой штатный интерфейс.

### 4.3 База не в git, а в GitHub Release
1.6 ГБ. GitHub блокирует push файлов больше 100 МБ, а еженедельный коммит такого
файла раздувал бы историю навсегда. Release — лимит 2 ГБ на ассет, вне истории
git, без квоты трафика (в отличие от Git LFS).

### 4.4 Turso, а не Cloudflare KV
Изначально была KV. На живом прогоне выяснилось: бесплатный тариф KV — **1000
операций записи в СУТКИ**, а машин 2.4 млн. Заливка падала с 429 и не могла
завершиться в принципе.

Перебрали: Supabase и Neon — 0.5 ГБ (мало, у нас ~350 МБ и растёт),
Cloudflare D1 — 5 ГБ, но 100 тыс. строк/сутки (первая заливка растянулась бы
на 25 дней). **Turso**: 5 ГБ, 10 млн записей строк в МЕСЯЦ, 500 млн чтений,
и это буквально SQLite — тот же диалект, что локально.

### 4.5 Перекупщик (סוחר) — не владелец
В истории владения `סוחר` — транзитная точка, машина у него не эксплуатируется.
Поэтому он не получает номер руки и ему не считается километраж. Показывается
обычной строкой таблицы с пустой ячейкой руки, приглушённой серым.

### 4.6 Тип КПП не отслеживается — и не может
`automatic_ind` есть **только в каталоге моделей**, а не в реестре по конкретной
машине. То есть это свойство модели, а не экземпляра, и «поменяться» у машины
физически не может. Ближайший честный сигнал — смена `degem_cd`
(переклассификация модели), она в списке отслеживаемых полей.

## 5. Грабли, уже собранные (НЕ наступать снова)

### 5.1 JOIN: обязателен `CAST(... AS TEXT)`
```sql
-- ПРАВИЛЬНО:
ON c.plate = CAST(CAST(TRIM(s.mispar_rechev) AS INTEGER) AS TEXT)
```
Две вещи разом:
- **Внутренний CAST AS INTEGER** срезает ведущие нули. Из API приходит
  `07488339`, в базе лежит `7488339`. Без него такие машины КАЖДУЮ неделю
  считались бы новыми заново.
- **Внешний CAST AS TEXT** обязателен для производительности. Без него сравнение
  TEXT-колонки с INTEGER-выражением не даёт SQLite использовать индекс, план
  вырождается в `SCAN` на каждую строку (2.4 млн × 2.4 млн) — прогон висел
  **16+ минут без движения**. С ним: `SEARCH ... (plate=?)`, 1.5 секунды.

Проверять планы через `EXPLAIN QUERY PLAN`, а не на глаз.

### 5.2 Массовые вставки — только внутри явной транзакции
`conn` открыт с `isolation_level=None`. Без явного `BEGIN` sqlite3 коммитит
каждую строку отдельно — миллионы fsync, часы простоя. Оборачивать в
`db.transaction(conn)`.

### 5.3 staging-таблицы удалять и делать VACUUM
Иначе они остаются в базе навсегда и удваивают её размер (было 1.19 ГБ вместо
600 МБ). Удаляются в конце прогона (`drop_staging_tables`), не сразу после
каждого ресурса — потому что `build_odometer_readings` джойнит
`staging_history` со `staging_main`.

### 5.4 Дублирующие индексы
`ownership` имеет `PRIMARY KEY (plate, baalut_dt, baalut)` — отдельный индекс по
`plate` был бы дублем (leftmost prefix) и раздувал бы файл. Убран.

### 5.5 Основной реестр — только нужные поля
Тянуть все 24 колонки = ~2 ГБ RAM у процесса, рискованно для раннера GitHub.
Запрашиваем 9 через параметр `fields=` → 418 МБ. См.
`COLLECTED_RESOURCE_FIELDS` в `shared/refdata.py`.

### 5.6 Заливка в Turso должна быть возобновляемой и с ретраями
Прогон упал на 940 000-й строке из 4 872 409 с **HTTP 502 Bad Gateway** —
обычный временный сбой. Было две ошибки:
- ретраев не было вообще (сотни запросов подряд — 502 практически неизбежна);
- курсор двигался только после ПОЛНОГО успеха, поэтому упавший прогон терял
  весь прогресс и следующий начинал с нуля → бесконечный цикл, сжигающий по
  ~1 млн записей квоты за попытку.

Сейчас: до 5 попыток с нарастающей паузой, курсор сохраняется **после каждой
пачки** отдельным запросом (после того, как пачка реально уехала).

### 5.7 Re-run в GitHub Actions берёт СТАРЫЙ коммит
Кнопки «Re-run jobs» и «Re-run failed jobs» перезапускают тот же commit SHA.
После исправления кода нужен **свежий запуск** через «Run workflow».

## 9. Что важно в стиле работы

- Проект писался «вслепую», без выполнения кода, поэтому **любое утверждение
  проверять запуском**, а не рассуждением. Почти все серьёзные проблемы выше
  вылезли только на живых данных.
- Обе версии интерфейса (`server/static/app.js` и
  `export/dist_template/static/app.js`) — почти дубликаты и держатся
  синхронными намеренно. Меняя логику в одной, переносить в другую.
- Не выдумывать данные, которых нет. Если поля нет в источнике (как КПП по
  машине или даты владения точнее месяца) — честно сказать, а не подгонять.
