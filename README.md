# carcheck — проверка авто по номеру (Израиль)

Личный инструмент проверки автомобиля перед покупкой по данным Минтранса
(data.gov.il) + собственная накопленная история пробега и номера двигателя,
которую государство нигде не публикует.

**Главный сценарий (после этого обновления ТЗ): GitHub Actions.** Раз в неделю
GitHub-хостед раннер сам скачивает свежие данные, сравнивает с прошлой неделей
и публикует статический сайт — никакой домашний компьютер держать включённым
не нужно. Компьютер нужен один раз — чтобы запушить репозиторий и включить
Pages/Actions.

Локальный сервер (Flask + .bat + Tailscale) оставлен как **необязательный**
вариант для проверки дома или отладки — см. раздел "Опционально: локальный сервер".

## Основной сценарий: GitHub Actions

### Что происходит

`.github/workflows/weekly.yml` по расписанию (по умолчанию — раз в неделю, понедельник
03:00 UTC) на **GitHub-хостед раннере**:

1. Чекаутит `main`.
2. Ставит зависимости (`pip install -r requirements.txt`).
3. Скачивает `collector/db/carcheck.sqlite3` — базу с прошлой недели — из **GitHub
   Release** (тег `db-latest`), а не из самого репозитория (см. пункт 5, почему).
4. Запускает `python collector/collector.py` — тянет свежие данные Минтранса
   постранично через JSON API `datastore_search` (через `package_show`, без хардкода
   URL — подробности и почему не сырой CSV см. в `collector/api_loader.py`), сравнивает
   с базой, дописывает изменения.
5. Запускает `python export/export.py` — собирает статический сайт (интерфейс +
   Cloudflare Pages Function) в `export/dist/`. **Данных по конкретным машинам в этой
   папке нет** — только код интерфейса и агрегированный `meta.json` (счётчики).
6. Заливает обновлённый `collector/db/carcheck.sqlite3` обратно в тот же GitHub Release
   (`db-latest`, с перезаписью). **В git база не коммитится** — на реальном объёме
   данных (миллионы строк) она весит 600+ МБ и растёт дальше, а GitHub блокирует
   `git push` файлов больше 100 МБ; обычный коммит к тому же раздувал бы историю
   репозитория на сотни МБ каждую неделю навсегда. GitHub Release — файл того же
   масштаба (лимит 2 ГБ на ассет), но вне истории git и без квоты трафика, в отличие
   от Git LFS.
7. Публикует `export/dist/` в ветку `gh-pages` (через `peaceiris/actions-gh-pages`) —
   её подхватывает Cloudflare Pages.
8. Запускает `python export/kv_upload.py` — заливает накопленную историю по машинам
   в Cloudflare KV (см. раздел "Деплой: Cloudflare Pages + Pages Functions + KV" ниже —
   это ключевой момент архитектуры: история уходит не на сайт, а в приватное
   key-value хранилище, читаемое только поштучно через отдельную функцию).

Сырые постраничные ответы JSON API (`collector/archive/*.jsonl.gz`) в git **не
попадают** — они существуют только на раннере во время джобы и потом пропадают вместе
с ним. Вся ценная выжимка (пробег по датам, номера двигателя, владение) уже лежит
в SQLite (в Release) и в Cloudflare KV.

### Как запустить (когда вернётесь за компьютер)

1. Создать новый репозиторий на GitHub (например `carcheck`, публичный — так решили).
2. Распаковать присланные файлы в папку с точной структурой из FILES.md.
3. Из папки проекта:
   ```
   git init
   git add .
   git commit -m "carcheck: первая версия"
   git branch -M main
   git remote add origin https://github.com/<ваш_логин>/carcheck.git
   git push -u origin main
   ```
4. На GitHub: **Settings -> Actions -> General -> Workflow permissions** — выбрать
   "Read and write permissions" (иначе workflow не сможет коммитить БД и пушить `gh-pages`).
5. **Сначала настроить Cloudflare** (KV namespace + секреты для GitHub Actions) — см.
   следующий раздел "Деплой: Cloudflare Pages + Pages Functions + KV", шаги 1-4 там.
   Без этого шаг заливки в KV просто ничего не сделает (аккуратно пропустится с
   понятным сообщением в логе), а сайт будет работать, но без накопленной истории.
6. Первый прогон: вкладка **Actions -> Weekly carcheck collector + export -> Run workflow**
   (не ждать понедельника). Первый прогон создаст `collector/db/carcheck.sqlite3` с нуля —
   `history` будет пустой (сравнивать пока не с чем), это ожидаемо, см. чек-лист ниже.
7. После первого успешного прогона появится ветка `gh-pages` с уже собранным сайтом
   (`index.html`, `static/`, `functions/`, `meta.json`). **Хостим её не встроенным GitHub
   Pages, а Cloudflare Pages** — см. следующий раздел, там же объясняется зачем и как
   привязать эту ветку к проекту Pages.

Никаких секретов для самого GitHub вручную заводить не нужно — `secrets.GITHUB_TOKEN`
создаётся GitHub автоматически для каждого workflow-запуска. Секреты `CF_*` (для Cloudflare)
нужно завести один раз вручную — см. следующий раздел.

### Расписание

По умолчанию `cron: "0 3 * * 1"` (понедельник, 03:00 UTC). Поменять — отредактировать
эту строку в `.github/workflows/weekly.yml`. Плюс всегда доступен ручной запуск через
**Actions -> Run workflow**, не дожидаясь расписания.

### Деплой: Cloudflare Pages + Pages Functions + KV

Требование, под которое сделана эта схема: **весь функционал, включая накопленную
историю (пробег по датам, смена двигателя, аномалии), должен быть доступен любому
посетителю сайта при поиске конкретного номера — без всякого логина, это и есть
главная ценность инструмента.** При этом должно быть технически невозможно (или хотя
бы очень затратно) скачать всю накопленную базу целиком, по всем машинам разом.

Это две разные задачи, и решают их два разных механизма:

- **Точечный доступ (открыт всем)** — сайт и живой поиск по data.gov.il полностью
  публичные, без логина. Это открытые госданные, ограничивать их незачем.
- **Защита от массовой выгрузки** — накопленная история хранится не как публично
  перечислимые файлы на сайте, а как записи в **Cloudflare KV** (key-value хранилище),
  ключ = номер машины. Прочитать конкретную запись можно только зная точный номер —
  через **Cloudflare Pages Function** `functions/api/history/[plate].js`, которая
  принимает ровно один номер за раз и не имеет способа отдать список/дамп всех ключей.
  Внутри этой же функции — свой рейт-лимит по IP (без платных фич Cloudflare, подробности
  ниже), чтобы затруднить перебор всего диапазона номеров скриптом.

(Более ранний вариант — публичные JSON-шарды `dist/data/XXX.json`, закрытые Cloudflare
Access — отменён: шарды по 300-999 файлам сами по себе перебираемы скриптом за минуты
без всякого логина, а Access либо закрывает всё целиком, либо не защищает от скрапинга
при точечном публичном доступе. Ни то, ни другое не подходило под требование "открыто
для одного номера, закрыто для выгрузки всей базы".)

**Настройка (один раз, в панели Cloudflare, бесплатно):**

1. Завести аккаунт на dash.cloudflare.com (бесплатный тариф).
2. **Workers & Pages -> KV -> Create a namespace.** Назвать, например, `carcheck-history`.
   Скопировать **Namespace ID** — понадобится и для привязки к Pages, и для GitHub Secrets.
3. **Workers & Pages -> Create -> Pages -> Connect to Git** -> выбрать репозиторий
   `carcheck` -> ветка для деплоя: `gh-pages` -> Build command: (пусто/none, сайт уже
   собран воркфлоу) -> Output directory: `/` (корень ветки gh-pages). После первого
   деплоя сайт будет доступен на `https://carcheck.pages.dev` (или на своём домене).
4. В настройках уже созданного Pages-проекта: **Settings -> Functions -> KV namespace
   bindings -> Add binding.** Variable name: **`CARCHECK_KV`** (именно так, это имя
   зашито в `functions/api/history/[plate].js`) -> KV namespace: `carcheck-history`
   из шага 2. Применить для Production (и Preview, если нужно).
5. Получить данные для GitHub Secrets:
   - **Account ID** — Workers & Pages -> Overview, справа на странице.
   - **API Token** — My Profile -> API Tokens -> Create Token -> шаблон "Edit Cloudflare
     Workers" подходит, либо создать кастомный токен с правом **Account -> Workers KV
     Storage -> Edit**.
   - **KV Namespace ID** — из шага 2.
6. В репозитории на GitHub: **Settings -> Secrets and variables -> Actions -> New
   repository secret**, завести три секрета:
   - `CF_API_TOKEN`
   - `CF_ACCOUNT_ID`
   - `CF_KV_NAMESPACE_ID`
7. Готово: со следующего прогона `.github/workflows/weekly.yml` шаг "Upload accumulated
   history to Cloudflare KV" будет находить эти секреты и заливать накопленную историю.
   Пока секреты не заведены, сайт работает нормально (живой поиск), а блок истории
   на любой машине будет честно показывать "история не накоплена" — это не ошибка,
   просто интеграция ещё не настроена.

**Анти-скрапинг в самой функции — будьте с собой честны насчёт уровня защиты.**
`functions/api/history/[plate].js` считает запросы по IP через ту же KV (ключ вида
`rl:<ip>:<минута>`, TTL ~70 секунд) и возвращает `429`, если с одного адреса пришло
больше 25 запросов за минуту. Это **не железная защита** — при желании её можно обойти
(смена IP, распределённый перебор). Она подобрана так, чтобы совершенно не мешать
обычному человеку, который проверяет 1-2 машины перед покупкой, но делала перебор
всего диапазона номеров (десятки миллионов вариантов) заметно медленнее и дороже,
чем оно того стоит — то есть **затрудняет и делает нерентабельным, а не гарантирует
невозможность**. Если в будущем захочется более строгую защиту — можно добавить
Cloudflare Turnstile (капчу) перед первым запросом или перейти на платный Cloudflare
Rate Limiting Rules; не сделано сейчас, только зафиксировано как возможное развитие.

## Опционально: локальный сервер

Вторичный сценарий — для проверки дома, когда компьютер и так включён, или для отладки.
Показывает то же самое, что и статический сайт, плюс работает без ожидания следующего
еженедельного прогона GitHub Actions (можно гонять `run_collector.bat` вручную хоть каждый день).

### Запуск

```
run_server.bat
```
Создаст `.venv`, поставит зависимости, поднимет Flask на `http://0.0.0.0:8000`.
В консоли будет выведен токен доступа и адреса (локальный, по имени компьютера, по IP).

Авторизация — токен в URL: `http://<адрес>:8000/?token=<токен>`. Токен генерируется один
раз и лежит в `server/secret_token.txt` (не коммитится, см. `.gitignore`). После первого
захода с `?token=...` браузер запоминает авторизацию в cookie на 30 дней.

### Доступ с телефона через Tailscale

1. Установить Tailscale (tailscale.com) на компьютер и на телефон, зайти под
   одним аккаунтом на обоих устройствах.
2. Сервер уже слушает `0.0.0.0` — ничего дополнительно настраивать не нужно.
3. На телефоне открыть `http://<Tailscale-имя-компьютера>:8000/?token=<токен>`
   (Tailscale-имя видно в приложении Tailscale на компьютере, обычно вида
   `имя-компьютера.tailXXXX.ts.net`).
4. **Порт на роутере пробрасывать не нужно и не следует** — Tailscale работает через
   исходящее соединение, это и есть весь смысл его использования здесь.

### Отключить уход Windows в спящий режим (актуально только для этого локального сценария)

Если хотите держать сервер доступным даже когда за компьютером никто не сидит:

- **Через параметры:** Параметры -> Система -> Питание и спящий режим -> "Спящий режим"
  выставить в "Никогда" (отдельно для "От сети").
- **Через PowerShell (от администратора), эквивалент:**
  ```powershell
  powercfg /change standby-timeout-ac 0
  powercfg /change hibernate-timeout-ac 0
  ```
  (`-ac` — режим "от сети"; для ноутбука на батарее используйте `-dc`, если нужно, но
  для сервера, который должен быть доступен всегда, обычно держат ноутбук на зарядке).

Учтите: если вы переходите на сценарий GitHub Actions как основной, эта настройка
не нужна вообще — сборка идёт на раннере GitHub, а не на вашем компьютере.

### Планировщик заданий Windows (локальный бэкап — параллельно с GitHub Actions)

GitHub Actions — основной сценарий и работает сам по себе, компьютер для него не нужен.
Но локальную копию `collector/db/carcheck.sqlite3` тоже удобно держать актуальной
(запасная копия на своём диске, независимая от GitHub) — для этого можно зарегистрировать
такую же еженедельную задачу в Планировщике заданий Windows, она никак не конфликтует
с GitHub Actions (это два независимых источника, каждый копит свою локальную БД):

```powershell
$action = New-ScheduledTaskAction -Execute "C:\путь\до\carcheck\run_all.bat"
$trigger = New-ScheduledTaskTrigger -Weekly -DaysOfWeek Monday -At 6am
$settings = New-ScheduledTaskSettingsSet -WakeToRun -StartWhenAvailable
Register-ScheduledTask -TaskName "carcheck weekly" -Action $action -Trigger $trigger -Settings $settings -Description "Сборщик + экспорт carcheck раз в неделю (локальный бэкап, параллельно с GitHub Actions)"
```

Выполнять из PowerShell от имени администратора, путь поправить под реальный.
`-WakeToRun` разбудит компьютер из сна специально для задачи (если он не выключен
физически, а именно "спит"). Если компьютер в момент запуска выключен физически —
задача просто не выполнится в этот раз, ничего не сломается, при следующем включении
`StartWhenAvailable` запустит её при первой возможности.

## Часть 3: מחירון העם (carlistprice.mot.gov.il) — не реализовано автоматически

`carlistprice.mot.gov.il` — SPA (одностраничное приложение), вся страница рендерится
JS-кодом после загрузки, реальные данные подгружаются отдельными запросами уже в браузере.
В среде, где готовился этот проект, не было браузера с исполнением JavaScript (только
простой HTTP-фетч), поэтому вытащить из скомпилированного бандла реальные адреса API не
получилось — фетч страницы отдаёт только пустую HTML-оболочку, а угадывать пути вида
`/api/...` вслепую бессмысленно (и невежливо по отношению к серверу министерства).

**Что нужно от вас**, чтобы включить эту интеграцию:

1. Открыть https://carlistprice.mot.gov.il/ в Chrome.
2. DevTools (F12) -> вкладка **Network** -> фильтр **Fetch/XHR**.
3. Ввести в поиске на сайте любую машину.
4. Найти в списке запрос, который вернул JSON с ценой (обычно содержит "price"/"mehir"/
   "search" в пути или в теле).
5. Правый клик по запросу -> **Copy -> Copy as cURL** -> прислать этот curl.

Каркас для интеграции уже готов в `server/price_meha.py` — там пояснено, что именно
вписать, когда появится реальный запрос.

## Как проверить, что всё работает (чек-лист из ТЗ)

Что удалось проверить **живыми запросами к data.gov.il** прямо во время подготовки
проекта (без выполнения кода — только прямые HTTP-запросы к API):

- Все resource_id из таблицы в ТЗ отвечают и возвращают ожидаемые поля.
- `package_show(shinui_mivne)` возвращает оба "жирных" ресурса с реальными `url`
  вида `https://e.data.gov.il/dataset/<package_id>/resource/<resource_id>/download/<resource_id>.csv`
  и `last_modified` — collector.py именно так их и резолвит, ничего не хардкодится.
- Три тестовых номера дали ровно то, что описано в ТЗ:
  - `5156286` — Suzuki Baleno 2017, `kilometer_test_aharon=129982`, 1 запись в history,
    поле `mispar_manoa=4026676`.
  - `2823923` — Subaru Forester 2002, в ресурсе истории (`56063a99...`) — 0 записей
    (машина старше 2017, как и ожидалось), при этом в ресурсе ADAS (`83bfb278...`) —
    запись есть (скидка числится).
  - `2947251` — не проверялся отдельным запросом в этой сессии, но логика идентична
    2823923 (машина 2004 года, вне покрытия истории) — стоит перепроверить при первом
    реальном прогоне.

Что **не проверено выполнением кода** (не было доступной среды исполнения Python/Bash
нигде в процессе подготовки), это предстоит сделать при первом реальном прогоне:
